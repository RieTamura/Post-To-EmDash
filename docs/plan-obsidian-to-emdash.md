# 計画書：Obsidian から EmDash へ記事を投稿する

作成日：2026-10-28（同日、ステップ1の結果で見直し）

## 1. やりたいこと

- Obsidian で書いた Markdown の記事を、このサイト（EmDash）のブログに投稿する。
- 画像・タグ・カテゴリー・抜粋も一緒に送る。
- 一度投稿した記事は、Obsidian で直してもう一度送ると、同じ記事が更新される（二重に投稿されない）。

## 2. 決まっていること

| 項目 | 決定 |
| --- | --- |
| 作り方 | Obsidian プラグイン（Post To Bluesky と同じ作り方） |
| 名前（仮） | Post To EmDash |
| 置き場所 | 新しいリポジトリ（`RieTamura/Post-To-EmDash`）。サイトのリポジトリとは分ける |
| 送り先 | このサイトのブログ（`posts` コレクション） |
| 合言葉 | EmDash の「個人用アクセストークン」（`ec_pat_…`）。Obsidian のキーチェーンに保存し、設定ファイルには書かない（Post To Bluesky と同じ） |

## 3. 決めたこと（2026-10-28、すべておすすめの案）

| # | 項目 | 決定 |
| --- | --- | --- |
| A | いつ送るか | コマンド（またはリボンのボタン）で、今開いている記事を送る |
| B | 送ったあとの状態 | 下書きで送る。frontmatter に `status: publish` と書いたときだけ、すぐ公開 |
| C | アイキャッチ | frontmatter の `cover` で指定した画像。指定がなければ本文の最初の画像 |
| D | 送り先 | 最初はブログ（posts）だけ |

## 4. 記事の書き方（Obsidian 側）

ノートの先頭（frontmatter）に、送りたい情報を書きます。

```yaml
---
title: 記事のタイトル          # なければノートのファイル名
slug: my-first-post            # URL の最後の部分。書かないとタイトルから自動（日本語の URL になる）
excerpt: タイムラインに出る短い紹介文
category: 開発                 # 1つ。サイトにある名前で書く
tags: [Web開発, ツール]          # いくつでも。サイトにない名前は新しく作る
cover: 画像/表紙.png            # アイキャッチ
status: draft                  # draft（下書き）か publish（公開）
---
```

投稿すると、プラグインが frontmatter に次の3行を書き足します（次に送るときに「同じ記事の更新」とわかるように）。

```yaml
emdash_id: 01M5…               # EmDash の記事の ID
emdash_url: https://…/posts/my-first-post
emdash_rev: MToy…              # 最後に送ったときの版。管理画面で直されたかを見分けるのに使う
```

### 本文の変換

| Obsidian の書き方 | サイトでの見え方 |
| --- | --- |
| 見出し・太字・斜体・取り消し線・リスト（入れ子も）・引用・コード・リンク・区切り線 | そのまま |
| 表 | 表（右寄せ・中央寄せも） |
| `- [ ]` / `- [x]`（チェックボックス） | ☐ / ☑ の付いた箇条書き |
| `$$ 数式 $$` | LaTeX のコードとして表示 |
| `![[画像.png]]` / `![](画像.png)` | 画像を EmDash にアップロードして、記事の中に表示 |
| `[[別のノート]]` | 相手もサイトに投稿済みならその記事へのリンク、まだなら普通の文字 |
| `> [!note] …`（コールアウト） | 引用として表示 |
| `==ハイライト==` | 普通の文字（印は外す） |
| `%%コメント%%` | 送らない |

## 5. 仕組み

```
Obsidian で「EmDash に投稿」を実行
      │  ① frontmatter と本文を読む
      │  ② 画像を見つけて EmDash にアップロードする（同じ画像は1回だけ）
      │  ③ Markdown を EmDash の本文の形式（Portable Text）に変える
      │     → プラグインの中の変換（src/convert.ts）。EmDash 公式と同じ形のブロックを作る
      │  ④ カテゴリー・タグを名前で探す（タグがなければ作る）
      │  ⑤ 記事を作る／更新する（emdash_id があれば更新。サイト側で直されていたら確認する）
      │  ⑥ status: publish なら公開する
      ▼
frontmatter に emdash_id・emdash_url・emdash_rev を書き足して、「投稿しました」と表示
```

- 通信は Obsidian の `requestUrl` を使います（Post To Bluesky と同じ。ブラウザの制限を受けずに、スマホ版の Obsidian でも動きます）。
- 公開すると、サイトのページのキャッシュは EmDash が自動で消すので、すぐにサイトに出ます。

### 使う API（ステップ1で確認済み）

| やること | API | メモ |
| --- | --- | --- |
| 画像のアップロード | `POST /_emdash/api/media`（multipart、`deduplicate=true`） | 同じ画像は同じ ID が返る（二重にアップロードされない） |
| カテゴリー・タグを探す | `GET /_emdash/api/taxonomies/{category|tag}/terms` | 名前（label）から slug を調べる |
| タグを作る | `POST /_emdash/api/taxonomies/tag/terms`（`label` だけ） | 同じ名前で作ると「-1」付きの別のタグができるので、必ず先に探す |
| 記事を作る | `POST /_emdash/api/content/posts` | `data`（title・excerpt・content・featured_image）、`slug`、`status: "draft"`、`taxonomies: { category: [slug], tag: [slug…] }` を1回で送れる |
| 記事を更新する | `PUT /_emdash/api/content/posts/{id}` | 前回の `_rev` を付ける。管理画面で直されていれば 409 で断られる |
| 公開する | `POST /_emdash/api/content/posts/{id}/publish` | 最新の `_rev` を付ける |

- **本文の画像**：`{ _type: "image", asset: { _ref: 画像の ID }, alt, width, height }` の形で入れる。公式の変換は `![](URL)` を `asset.url` にするので、アップロードした画像は ID に置きかえる。
- **アイキャッチ**：`featured_image` に `{ id, provider: "local", alt, width, height, meta: { storageKey } }` を入れる。
- **存在しないタグ・カテゴリー**：slug が間違っていると記事ごと断られる（400）。送る前に必ず確かめる。
- **公開済みの記事を更新したとき**：EmDash では「公開中の版はそのまま、変更は下書き」になる。`status: publish` なら続けて公開、そうでなければ管理画面で公開する。

## 8. 気をつけること・わからないこと

- **トークンの作り方**：管理画面の「APIトークン」で作ります。必要な権限は `content:read`・`content:write`・`media:write` の3つだけです（ステップ1で、この3つだけのトークンで全部の操作ができることを確認済み。タグを作る権限も `content:write` に含まれます）。有効期限も付けられます。
- **トークンの扱い**：トークンがあれば、だれでもあなたのサイトに記事を書けます。Obsidian のキーチェーンにだけ保存し、保管庫の同期（Obsidian Sync や Git）に乗らないようにします。キーチェーンは端末ごとなので、パソコンとスマホでそれぞれ入力が必要です。
- **変換できない書き方**：Obsidian の独自の書き方（埋め込みノート `![[ノート]]`、表、数式、Mermaid の図など）は、そのままでは EmDash で表示できません。表は表に変換します（2026-10-28 ステップ4で対応）。数式はコードとして表示し、埋め込みノートは送りません。
- **サイトの管理画面で直した記事**：前回送ったときの版（`emdash_rev`）を付けて更新するので、管理画面で直されていると EmDash が断ります（409）。そのときは「サイト側で変更があります。上書きしますか？」と聞いて、「はい」のときだけ上書きします（ステップ1で、古い版での更新が断られることを確認済み）。
- **英語版**：最初の版では日本語の記事だけを送ります。
- **EmDash の更新**：変換はプラグインの中で作っています（下の「ステップ4で決めたこと」）。EmDash が本文の形式を大きく変えたら、合わせて直します。

## 9. ステップ1の結果（2026-10-28）

開発サーバーで、プラグインと同じ条件（権限3つだけのトークン、ブラウザの Origin ヘッダーなし）で試しました。テストで作った記事・画像・タグ・トークンは、確認後に消しました。

| 確かめたこと | 結果 |
| --- | --- |
| 公式の変換（見出し・太字・リンク・リスト・画像・コード） | 期待どおりのブロックになる |
| 画像のアップロード（2回） | 1回目 201、2回目 200 で同じ ID（重複しない） |
| カテゴリーの一覧 | 名前と slug が取れる（開発=development など） |
| 日本語の名前だけでタグを作る | 作れる（slug も日本語になる）。同じ名前で2回作ると「-1」付きの別のタグになる |
| 下書きで記事を作る（本文・抜粋・アイキャッチ・カテゴリー・タグを1回で） | 作れる。タグも付いている |
| 更新 | できる。古い `_rev` での更新は 409 で断られる |
| 公開 | できる |
| 存在しないタグの slug | 400 で記事ごと断られる |
| slug で記事を探す | `GET /content/posts/{slug}` で取れる |
| 公開したページの表示 | アイキャッチと本文の画像の両方が表示される |

## 11. ステップ2〜4の結果（2026-10-28）

- **ステップ2**：公開リポジトリ RieTamura/Post-To-EmDash を作り、ひな形を置いた。テスト用の保管庫（emdash-test）で読み込めることを確認。
- **ステップ3**：設定画面に「接続を確かめる」ボタン。記事一覧（`GET /content/posts?limit=1`、`content:read` で足りる）が読めるかで確かめる。`/auth/me` は管理者の権限が要るので使わない。開発サーバーで「接続できました」を確認。
- **ステップ4で決めたこと**：EmDash 公式の変換（markdownToPortableText）は使わず、プラグインの中で変換する。理由：
  - 公式の変換は、1行ごとに別の段落にする（Obsidian の「続いた行は同じ段落の中の改行」と見た目が変わる）
  - `*斜体*`、入れ子の強調、表、`~~~` のコード、字下げがタブの箇条書きを扱わない
  - 使うには `emdash` パッケージをまるごと入れる必要があり、重い
  - 作るブロックの形は公式と同じ（`block`・`code`・`image`・`break`・`table`）。サイトの表示はそのまま使える
- **ステップ4の確認**：テスト29個（`npm test`）。変換した記事を開発サーバーで公開して、見出し・改行・強調・リンク・入れ子の箇条書き・コールアウト・区切り線・表・コードがサイトで正しく表示されることを確認（テストの記事は削除済み）。

## 12. ステップ5の結果（2026-10-28）

- 下書きで作る・更新する・`status: publish` で公開する、を Obsidian のテスト用の保管庫から開発サーバーに送って確認（あなたが Obsidian で確認）。frontmatter に `emdash_id`・`emdash_url`・`emdash_rev` が書き足される。
- サイト側で直されていた（409）ら上書きしてよいか、削除されていた（404）ら新しい記事として送るかを聞く。
- わかったこと：
  - 削除した記事はゴミ箱に残り、slug もふさがったまま。同じ slug で作ると `SLUG_CONFLICT`（409）で断られるので、「slug を変えるか、ゴミ箱から完全に削除する」と案内する。
  - 更新では、送らなかった項目はサイトの値がそのまま残る（frontmatter から excerpt を消しても、サイトの抜粋は消えない）。
  - 管理画面で記事を開いていると `ENTRY_LOCKED` で断られることがある。

## 13. ステップ6（2026-10-28、Obsidian から開発サーバーに送って確認済み）

- 画像：保管庫の画像（`![[…]]` と同じ探し方）と http(s) の画像を、`POST /media`（multipart を自前で組み立てる。`deduplicate=true`）でアップロード。本文の画像は `asset: { _ref, url, provider: "local" }` と、画像の大きさ・blurhash・dominantColor。`![[画像|300]]` の大きさは `displayWidth`。見つからない画像は外して、名前を知らせる。
- アイキャッチ：`cover` の画像。なければ本文の最初の画像。管理画面と同じ形（`provider: "local"`, `id`, `meta.storageKey` など）。
- カテゴリー・タグ：名前（大文字小文字は気にしない）か slug で探す。入れ子のカテゴリーも探す。タグは無ければ作る（`content:write` で作れることを確認）。カテゴリーは作らず、使えるカテゴリーを知らせる。frontmatter に書いていない方は送らない（管理画面で付けたものを消さないため）。
- 開発サーバーで、アップロード（同じ画像は同じ ID）・タグ作成・カテゴリー・アイキャッチ・本文の画像がサイトに出ることを確認（テストの記事・タグ・画像は削除済み）。
- Obsidian から開発サーバーに送った記事で、アイキャッチ・本文の画像・カテゴリー・タグが表示されることを確認（あなたが確認）。

## 14. ステップ7の結果（2026-10-28）

- 本番の管理画面で、権限3つ（コンテンツの読み取り・書き込み、メディア書き込み）のトークンを作り、Obsidian のテスト用の保管庫から本番サイトに下書きを1本送った。
- 管理画面で、タイトル・本文（改行・画像・入れ子の箇条書き）・アイキャッチ・slug・タグが入っていることを確認（あなたが確認）。メディア読み取りの権限はいらない。
